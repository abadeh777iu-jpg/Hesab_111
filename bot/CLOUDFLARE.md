# راه‌اندازی روی Cloudflare Workers

**قیمت و هوا و هشدار بارش:** [راهنمای داده‌های اینترنتی](INTERNET.md). این قابلیت‌ها فقط در نسخهٔ Cloudflare فعال‌اند.

کد در GitHub می‌ماند؛ Worker روی Cloudflare اجرا می‌شود. نیاز به VPS، کامپیوتر همیشه‌روشن یا دامنه شخصی نیست. فایل `wrangler.jsonc` اتصال Durable Objects را هم تعریف می‌کند؛ ربات را به‌صورت **Worker** بسازید، نه Pages یا سایت React.

## ۱. حساب و کلیدها

- یک حساب Cloudflare بسازید و بخش **Workers & Pages** را فعال کنید. یک زیر‌دامنه `workers.dev` برای حساب انتخاب کنید، اگر پنل درخواست کرد.
- در تلگرام از حساب رسمی **@BotFather** با `/newbot` توکن بگیرید.
- در OpenRouter کلید API، اعتبار محدود و شناسه دقیق یک مدل چت با پشتیبانی از پیام system آماده کنید. محدودیت هزینه را در پنل OpenRouter هم تنظیم کنید.
- Node.js نسخه ۲۲ یا جدیدتر روی کامپیوترتان نصب باشد. اگر نصب/دسترسی ترمینال ندارید، از راه اتصال مخزن در بخش ۶ استفاده کنید.

**هیچ‌کدام از توکن‌ها، کلیدها یا فایل‌های خصوصی را در چت یا گیت‌هاب نگذارید.** رمز عبور یا توکن Cloudflare را هم برای کسی نفرستید.

## ۲. نصب ابزار و انتخاب مدل

داخل پوشه همین پروژه در ترمینال:

```sh
npm ci
npx wrangler login
```

فرمان دوم مرورگر را برای ورود مستقیم به Cloudflare باز می‌کند؛ لازم نیست رمز یا توکن را در ترمینال یا چت بنویسید.

پس از ساخت Worker، در **Settings → Variables and Secrets** متغیرهای زیر را با نوع **Text** ثبت کنید (اگر Worker از قبل ساخته شده، همین حالا انجام دهید):

- `OPENROUTER_MODEL`: شناسه دقیق مدل از OpenRouter؛ مقدار خالی عمداً مانع پاسخگویی می‌شود.
- `TELEGRAM_ALLOWED_USER_IDS`: برای تست، شناسه عددی تلگرام خودتان. خالی بودن در این نسخه یعنی ربات غیرفعال است. چند شناسه را با کاما جدا کنید. برای دسترسی عمومی فقط پس از تست، مقدار را `*` کنید؛ هر کاربر می‌تواند از اعتبار شما مصرف کند.
- `BOT_STYLE`: لحن و نمونه‌های ساختگی شبیه حرف‌زدن خودتان، بدون داده خصوصی.
نام Worker در `wrangler.jsonc` برابر `hesab-111` است و باید با نام پروژهٔ کلودفلر یکسان باشد. برای تغییر نام، فقط مقدار `name` را ویرایش کنید. تنظیم `keep_vars: true` متغیرهای ثبت‌شده در پنل را در انتشارهای بعدی حفظ می‌کند.

اگر شناسه عددی‌تان را نمی‌دانید، می‌توانید با یک ابزار معتبر دریافت شناسه در تلگرام بررسی کنید؛ توکن BotFather یا کلید OpenRouter برای دریافت شناسه لازم نیست. شناسه عددی با نام کاربری `@...` متفاوت است. شناسه کاربران مجاز را در پنل ثبت کنید، نه در Git. اگر آن را به‌صورت Secret می‌خواهید، همان متغیر را با نوع Secret بسازید؛ متغیر هم‌نام را دوبار تعریف نکنید.

## ۳. انتشار و ثبت Secrets

```sh
npm run bot:cf:deploy
```

آدرس خروجی شبیه `https://hesab-111.YOUR-SUBDOMAIN.workers.dev` است. تا تکمیل تنظیمات، webhook پاسخ فعال ندارد. سپس:

```sh
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put OPENROUTER_API_KEY
```

هر فرمان مقدار را به‌صورت ورودی محرمانه از شما می‌گیرد. کلیدها را در خود فرمان یا فایل پیکربندی ننویسید.

برای رمز مستقل webhook یک مقدار تصادفی بسازید:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

خروجی را خصوصی نگه دارید؛ سپس با این فرمان همان مقدار را در Cloudflare ثبت کنید:

```sh
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET
```

این رمز باید بین ۳۲ تا ۲۵۶ کاراکتر از حروف انگلیسی، اعداد، `_` یا `-` باشد. با توکن تلگرام و کلید OpenRouter متفاوت است. فقط درخواست‌های تلگرام دارای همین رمز اجازه ورود دارند.

## ۴. اتصال یک‌باره تلگرام به Worker

### راه ساده با گوشی (بدون ترمینال)

پس از انتشار آخرین نسخه، مسیر `/setup` را به آدرس **Worker خودتان** اضافه کنید. برای این پروژه:

`https://hesab-111.abadeh-gamenet.workers.dev/setup`

در این صفحه فقط رمز `TELEGRAM_WEBHOOK_SECRET` را وارد کنید و دکمه اتصال به تلگرام را بزنید. **توکن تلگرام و کلید OpenRouter را در این فرم وارد نکنید.** این دو فقط در Secrets کلودفلر می‌مانند. رمز در URL، localStorage یا لاگ برنامه قرار نمی‌گیرد؛ درخواست ثبت فقط از همان مبدا با رمز صحیح پذیرفته می‌شود. صفحه از منابع شخص ثالث استفاده نمی‌کند و cache نمی‌شود. هر کسی که رمز را داشته باشد می‌تواند اتصال را دوباره ثبت کند، پس محرمانه نگهش دارید.

این کار webhook قبلی همین ربات را جایگزین می‌کند. پس از موفقیت، در تلگرام `/start` و سپس یک پیام معمولی بفرستید. پیام موفقیت فقط ثبت اتصال را تأیید می‌کند؛ صحت اعتبار و پاسخ مدل با پیام واقعی آزمایش می‌شود. پس از تغییر URL یا رمز، اتصال را دوباره ثبت کنید.

### راه جایگزین با کامپیوتر


اگر نسخه قبلی با `npm run bot` یا سرویس دیگری در حال اجراست، اول آن را متوقف کنید. یک توکن را هم‌زمان با long polling و webhook استفاده نکنید.

```sh
cp .env.bot.example .env.bot
```

فایل `.env.bot` را فقط روی دستگاه خودتان با ویرایشگر باز کنید و برای ثبت webhook این دو مقدار را پر کنید:

```dotenv
TELEGRAM_BOT_TOKEN=توکن_واقعی_ربات
TELEGRAM_WEBHOOK_SECRET=همان_رمز_تصادفی_ثبت_شده_در_کلودفلر
```

روی macOS/Linux دسترسی فایل را محدود کنید:

```sh
chmod 600 .env.bot
```

حالا **آدرس واقعی خروجی deploy** را جای آدرس نمونه بگذارید:

```sh
npm run bot:webhook -- https://hesab-111.YOUR-SUBDOMAIN.workers.dev
```

اسکریپت توکن را از فایل خصوصی می‌خواند؛ در URL مرورگر یا آرگومان فرمان قرار نمی‌دهد. این فرمان آدرس webhook فعلی ربات را جایگزین می‌کند؛ اگر ربات دیگری از آن استفاده می‌کند، قبل از اجرا بررسی کنید. پیام‌های معوق تلگرام عمداً حذف نمی‌شوند. اگر توکن قبلاً استفاده شده، ممکن است پیام‌های معوق هم پردازش شوند.

در تلگرام `/start` بفرستید و بعد یک پیام معمولی. کامپیوترتان بعد از این مرحله می‌تواند خاموش باشد.

## ۵. بررسی و عیب‌یابی

- بازکردن آدرس اصلی Worker باید `Telegram support bot` نشان دهد؛ این فقط زنده‌بودن Worker است، نه صحت کلیدها.
- بازکردن `/webhook` در مرورگر خطای 405 طبیعی است؛ این مسیر برای درخواست POST تلگرام است.
- اگر پاسخ نمی‌گیرید: Secrets، تطابق رمز webhook، شناسه مجاز، شناسه مدل، اعتبار OpenRouter و آدرس نهایی Worker را بررسی کنید. پس از تغییر آدرس یا رمز، فرمان ثبت webhook را دوباره اجرا کنید.
- لاگ‌کردن متن پیام، بدنه درخواست، هدرها و خطاهای خام شبکه را فعال نکنید؛ URL خطای تلگرام ممکن است توکن داشته باشد. Observability برنامه عمداً در تنظیمات غیرفعال است؛ سیاست ثبت داده زیرساخت جداست.
- برای قطع موقت پاسخگویی، `TELEGRAM_ALLOWED_USER_IDS` را خالی و دوباره deploy کنید. برای خاموشی کامل، Worker را از پنل غیرفعال یا حذف کنید و webhook تلگرام را با ابزار معتبر مدیریت ربات حذف کنید. خاموشی باعث حذف خودکار داده‌های سرویس‌های دیگر نمی‌شود.
- اعتبار و مصرف هر دو سرویس را کنترل کنید. سقف پلن‌ها و امکان استفاده از Durable Objects را در حساب خودتان بررسی کنید؛ رایگان‌بودن دائمی یا نامحدود تضمین نمی‌شود.

## ۶. انتشار خودکار از GitHub (اختیاری)

بعد از اینکه تغییرات همین شاخه در GitHub قرار گرفتند، می‌توانید در بخش Workers & Pages یک Worker با اتصال به مخزن بسازید. اگر اتصال GitHub را مجاز می‌کنید، فقط دسترسی مخزن لازم را بدهید.

تنظیم‌ها:

- مخزن: `abadeh777iu-jpg/Hesab_111`
- شاخه این کار: `arena/8f9826a1-hesab-111`
- پوشه ریشه: ریشه مخزن
- نصب وابستگی‌ها: `npm ci` (اگر پنل خودکار انجام نمی‌دهد)
- فرمان Build: خالی؛ اگر اجباری بود `npm run bot:cf:check`
- فرمان Deploy: `npm run bot:cf:deploy`
- نام Worker باید با `name` در `wrangler.jsonc` یکی باشد.

از **Build command سایت Vite** یا Pages استفاده نکنید. نام و ترتیب گزینه‌های پنل ممکن است تغییر کند. Secrets را در **تنظیمات اجرایی Worker → Variables and Secrets** ثبت کنید، نه فقط متغیرهای محیط Build. اگر پروژه هنوز فقط در فضای کار فعلی است، اتصال به GitHub تغییرات ذخیره‌نشده در مخزن راه‌دور را نمی‌بیند.

پس از اولین انتشار، مرحله ثبت webhook همچنان لازم است. بعد از آن، مادامی که URL و رمز تغییر نکند، برای هر تغییر کد لازم نیست webhook را دوباره ثبت کنید.

## حافظه، ایمنی و محدودیت‌ها

- این نسخه برخلاف اجرای محلی، حداکثر ۳۰ پیام اخیر را در فضای خصوصی Durable Objects کلودفلر نگه می‌دارد؛ این موضوع در `/about` و `/privacy` گفته می‌شود. پیام `/start` کوتاه است؛ بار اول یک اطلاع کوتاه دربارهٔ احوال‌پرسی خودکار و روش لغو هم دارد. داده به مرورگر فرستاده نمی‌شود و API عمومی خواندن تاریخچه وجود ندارد.
- تاریخچه پس از ۳۰ دقیقه بی‌فعالیتی با alarm از حافظهٔ فعال برنامه حذف می‌شود؛ اجرای cleanup ممکن است با تأخیر زیرساخت مواجه شود. حتی اگر alarm دیر اجرا شود، تاریخچه منقضی در درخواست بعدی استفاده نمی‌شود. `/reset` تاریخچه فعال را پاک می‌کند؛ اثر حذف بر نسخه‌های پشتیبان Cloudflare تابع سیاست خود سرویس است.
- هر کاربر صف مستقل دارد. سقف فاصله درخواست مدل ۴ ثانیه است. پیام متنی ۶۰۰۰ کاراکتر، خروجی ۳۲۰ توکن، مهلت پاسخ مدل ۲۰ ثانیه است. Worker تا پایان پردازش پاسخ HTTP را باز نگه می‌دارد؛ کار پس‌زمینهٔ بی‌تضمین با `waitUntil` استفاده نمی‌شود.
- ۱۰۰ شناسه به‌روزرسانی اخیر هر کاربر تا زمان انقضای جلسه برای کاهش پردازش تکراری نگه داشته می‌شود. شناسه قبل از فراخوانی مدل ثبت می‌شود؛ خرابی وسط کار ممکن است پاسخ را از دست بدهد. ارسال exactly-once تضمین نمی‌شود؛ برای تلاش دوباره یک پیام تازه بفرستید. این پیاده‌سازی صف پایدار با تحویل تضمینی نیست.
- ربات درمانگر یا سرویس بحران نیست. دستور ایمنی مدل تضمین‌کننده تشخیص خطر نیست. پیش از انتشار عمومی، لحن فارسی و واکنش به سناریوهای حساس را با مدل منتخب آزمایش کنید.


## جواب کوتاه، نظر داخل کادر و احوال‌پرسی فردا

- دستور مدل روی جواب معمولاً ۱ تا ۳ جمله، حدود ۲۰ تا ۶۰ کلمه، با ۲ تا ۴ ایموجی مرتبط تنظیم شده است. در موضوع حساس یا برای ایمنی، لحن و طول متناسب می‌شود. این‌ها دستور مدل هستند و تضمین خروجی دقیق نیستند؛ سقف تولید ۳۲۰ توکن است.
- حافظه، ۳۰ پیام کاربر و ربات در مجموع (حدود ۱۵ رفت‌وبرگشت) است، نه ۳۰ گفتگوی کامل. مدل حداکثر همان سابقه به‌علاوه پیام جدید را می‌گیرد. انقضای متن گفتگو همچنان ۳۰ دقیقه بی‌فعالیتی است؛ افزایش تعداد پیام مدت نگهداری را افزایش نمی‌دهد.
- مدل می‌تواند بخش نظر را با `[OPINION]...[/OPINION]` مشخص کند. این بخش به نقل‌قول بومی تلگرام با عنوان «💬 نظر امیر» تبدیل می‌شود؛ HTML تولیدشده توسط مدل کاملاً escape می‌شود. شیشه‌ای/blur واقعی و CSS سفارشی در پیام عادی تلگرام ممکن نیست؛ رنگ و ظاهر کادر به کلاینت و تم مخاطب بستگی دارد.
- احوال‌پرسی در نسخهٔ Cloudflare پس از اولین گفتگو یا `/start` و **ارسال موفق اطلاع کوتاه** خودکار فعال می‌شود؛ دستور `/followup` لازم نیست. اطلاع یک‌باره فقط امکان پیام‌دادن و روش لغو `/stop` را می‌گوید؛ جزئیات خبر هوا یا زمان آن در پیام شروع نمایش داده نمی‌شود. اگر ارسال اطلاع شکست بخورد، زمان‌بندی خودکار فعال نمی‌شود. تنها انتشار نسخه جدید برای کاربران غیرفعال زمان‌بندی تازه ایجاد نمی‌کند؛ کاربران قبلی در گفتگوی بعدی اطلاع را می‌بینند.
- پس از فعال‌سازی، یک پیام عمومی «امروز چطوری؟» حدود ۲۴ ساعت بعد از آخرین پیام متنی معتبر ارسال می‌شود. زمان با پیام جدید از نو حساب می‌شود. تا وقتی مخاطب پیام تازه نفرستد، پیام روزانهٔ تکراری ارسال نمی‌شود. بعد از پیام تازه، اگر کاربر پیگیری را لغو نکرده باشد، زمان‌بندی دوباره فعال می‌شود.
- `/stop` همهٔ پیام‌های خودکار (احوال‌پرسی و هوا) را خاموش و `/reset` شهر را هم حذف می‌کند. این فرمان‌ها زمان‌بندی احوال‌پرسی را قطع و شناسهٔ چت و موعد ذخیره‌شده را حذف می‌کنند. فقط ترجیح خاموشی نگه داشته می‌شود تا پیام تازه، انقضای تاریخچه، راه‌اندازی مجدد یا `/start` آن را بی‌اجازه فعال نکند. فعال‌سازی دوباره فقط با `/followup` است. `/start` برای مخاطبی که پیگیری را لغو نکرده، موعد را از نو حساب می‌کند.
- زمان‌بندی از alarm پایدار Durable Objects استفاده می‌کند؛ Cron یا کامپیوتر روشن لازم نیست. حذف تاریخچه بعد از ۳۰ دقیقه، زمان‌بندی را حذف نمی‌کند. شناسهٔ چت و موعد، جدا از متن گفتگو ذخیره می‌شوند. پیام احوال‌پرسی بدون فراخوانی مدل و بدون استفاده از متن منقضی‌شده تولید می‌شود.
- زمان ارسال دقیق تا ثانیه تضمین نمی‌شود. برای کاهش تکرار، موعد پیش از ارسال مصرف می‌شود؛ خرابی بین ثبت و ارسال ممکن است پیام را از دست بدهد و ارسال مجدد خودکار نداریم. در خطای ارسال (از جمله مسدودکردن ربات) یا لغو دسترسی کاربر از allowlist، شناسهٔ چت و موعد حذف و پیگیری خاموش می‌شود؛ ترجیح خاموشی حفظ می‌شود. برای فعال‌سازی مجدد مخاطب باید `/followup` بفرستد.
- برای امتحان نسخه جدید، پس از انتشار `/start` بفرستید تا سابقهٔ دستورهای قبلی پاک شود؛ بار اول اطلاع کوتاه را می‌بینید و پیگیری فعال می‌شود، مگر قبلاً لغوش کرده باشید. در این حالت فقط اگر خودتان می‌خواهید `/followup` بفرستید. اتصال webhook و کلیدهای موجود نیاز به تنظیم دوباره ندارند.
